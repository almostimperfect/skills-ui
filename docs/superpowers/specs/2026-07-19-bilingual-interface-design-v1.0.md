# 中英文双语界面设计 v1.0

- 日期：2026-07-19
- 目标分支：`development`
- 目标用户：使用 skills-ui 管理本机 Skill、项目与 Agent 的技术人员
- 支持语言：简体中文（`zh-CN`）与英文（`en`）

## 目标

为 skills-ui 增加完整的中英文界面和无需刷新页面的语言切换能力。首次访问跟随浏览器或操作系统语言；用户主动切换后持久保存选择。双语界面必须覆盖完整桌面业务流程，不改变 API、磁盘数据、Skill 名称或其他技术标识。

## 非目标

- 不支持繁体中文或中英文之外的第三种语言。
- 不翻译 Skill 名称、Agent 名称、项目路径、仓库地址、命令、文件名和 API 字段值。
- 不改变服务端 API、持久化格式或 Skill 安装逻辑。
- 不引入远程翻译服务、运行时语言包下载或自动机器翻译。
- 不为不同语言创建不同 URL。

## 产品语言规则

- `Skill` 保持英文，不翻译为“技能”。
- 中文面向技术人员，使用简洁、直接、可执行的措辞。
- 稳定产品概念采用一致译法：
  - Dashboard：概览
  - Skills：Skills
  - Projects：项目
  - Global install：全局安装
  - Project install：项目安装
  - Catalog only：仅目录
  - Scan now：重新扫描
- Skill 名称、项目名、Agent、路径和来源通过插值进入翻译文案，原值不变。

## 国际化架构

在 `src/web/i18n/` 下建立轻量、类型安全的项目内国际化层，不新增第三方依赖。

### 模块边界

- `translations.ts`：英文基准词典、完整的简体中文词典、翻译键与参数类型。
- `locale.ts`：语言类型、浏览器语言检测、存储读取与写入、日期和复数辅助逻辑。
- `I18nProvider.tsx`：React Context、当前语言状态、`t()`、`setLocale()` 与已知错误本地化。
- `useI18n.ts` 或同模块导出：供页面和组件读取国际化能力的稳定 Hook。

英文词典是翻译键的类型来源。简体中文词典必须满足同一键集合；缺失键在 TypeScript 构建阶段失败，不能静默回退造成半中文界面。

### 初始化与持久化

应用启动时按以下顺序选择语言：

1. 读取 `localStorage` 中的 `skills-ui.locale`。
2. 仅当值为 `en` 或 `zh-CN` 时采用该值。
3. 没有有效存储值时，按顺序检查 `navigator.languages` 和 `navigator.language`。
4. 任一语言标签为 `zh` 或以 `zh-` 开头时选择 `zh-CN`，否则选择 `en`。

用户切换语言后立即：

- 更新 React 状态，不刷新页面；
- 写入 `localStorage`；
- 更新 `document.documentElement.lang`；
- 更新页面标题。

如果浏览器阻止存储访问，切换仍在当前会话生效，界面不显示技术错误。

### 翻译接口

页面通过 `t(key, params?)` 获取文案。动态参数使用具名插值，例如 Skill 名称、项目名、Agent 和数量。日期使用 `Intl.DateTimeFormat` 按当前语言格式化；需要数量变化的完整句子使用独立翻译键，不依赖英文复数拼接。

## 错误本地化

已知接口错误根据稳定的完整错误文本或稳定前缀映射为当前语言。映射至少覆盖当前核心流程中的：

- Skill 或项目不存在；
- 路径必须为绝对路径；
- 来源不存在或不可重新安装；
- 全局继承状态不允许直接项目安装；
- 必须先移除全部安装才能忘记 Skill；
- 项目注册、Agent 更新、安装、移除、扫描和维护失败的通用兜底。

未知错误保留服务端安全处理后的原文，使技术用户仍能诊断问题。前端不得拼接状态码、原始命令、本机真实主目录或令牌。

## 语言切换器

语言切换器位于现有侧栏底部，与主导航分区，包含两个明确按钮：`中文` 与 `English`。

- 当前语言使用选中样式并设置 `aria-pressed="true"`。
- 两个按钮都有与当前界面语言一致的可访问名称。
- 桌面布局中固定在侧栏底部；窄窗口中进入导航区域并保持可见。
- 切换不改变当前路由、筛选、已加载数据或表单内容。
- 不使用国旗表达语言。

## 翻译覆盖范围

以下界面必须完整迁移到词典：

- 全局布局：产品副标题、导航与语言切换器。
- Dashboard：标题、扫描时间、扫描按钮、统计项、健康项、首次使用引导和错误反馈。
- Skills：标题、搜索、范围筛选、全局 Agent 目标、列表状态、来源状态、安装/卸载动作、空状态和安装弹窗。
- Skill 详情：返回入口、安装范围、项目目标、状态说明、维护、恢复、忘记、全局拆分及全部确认和反馈。
- Projects：标题、添加表单、路径说明、Agent 范围、注册、移除、空状态及反馈。
- 项目详情：统计、批量安装/卸载、矩阵状态、单项动作、确认与结果摘要。
- 通用交互：加载、进行中、成功、失败、无数据、不可用、确认提示、`title`、`aria-label` 与表单标签。

动态的 Skill 描述属于来源元数据，不做翻译。

## 组件迁移策略

根节点在 `QueryClientProvider` 内、路由外包裹 `I18nProvider`。`Layout` 渲染语言切换器。各页面和组件使用 `useI18n()`，不从模块级常量中固定生成英文标签；依赖语言的数组、筛选器和状态描述在组件渲染或 `useMemo` 中生成。

确认提示继续使用现有 `window.confirm`，但完整文案改由词典生成。API 返回的错误先通过 `localizeError()` 转换，再进入现有 `alert` 或 `status` 区域。

## 测试策略

### 单元测试

为国际化核心增加测试，覆盖：

- 有效持久化语言优先于浏览器语言；
- 中文浏览器语言选择 `zh-CN`；
- 非中文浏览器语言选择 `en`；
- 无效存储值被忽略；
- 中英文插值结果正确；
- 已知错误被翻译；
- 未知错误原样返回。

### Playwright 桌面 E2E

新增双语行为测试，覆盖：

1. 中文浏览器环境首次进入显示中文导航和概览。
2. 切换为 English 后当前页面立即变为英文。
3. 刷新页面后保持用户选择。
4. 中文模式下安装、移除或全局拆分的确认提示为中文且包含动态影响范围。
5. 已知服务端错误显示中文；未知安全错误保留原文。

现有英文 E2E 在测试启动时显式设置 `skills-ui.locale=en`，避免执行机器语言影响基线，并继续验证全部原业务流程。

### 完成前验证

## 验收标准

- 中文系统或浏览器首次打开时显示完整简体中文界面。
- 非中文环境首次打开时显示英文界面。
- 用户可以从任意页面切换语言，当前业务上下文不丢失。
- 刷新或重新打开后保持最后一次主动选择。
- 中文模式下核心页面不存在成段英文固定文案；允许保留约定的技术标识和未知错误原文。
- 英文模式保持现有业务能力和测试行为。
- 所有确认提示、错误、状态和辅助文本与当前语言一致。
- 不新增运行时依赖，不修改服务端或安装数据。
